# Contributing

Thank you for your interest in contributing to the Generic SQL API Framework.

We welcome bug reports, feature suggestions, documentation improvements, and code contributions.

---

# Getting Started

1. Fork the repository.
2. Clone your fork.

```bash
git clone https://github.com/your-username/generic-sql-api-framework.git
```

3. Create a new branch.

```bash
git checkout -b feature/my-feature
```

---

# Development Guidelines

Please follow these guidelines when contributing:

- Write clean and readable code.
- Keep functions focused on a single responsibility.
- Follow the existing project structure.
- Avoid breaking backward compatibility whenever possible.
- Add documentation for new features.
- Test changes before submitting.

---

# Reporting Issues

When reporting an issue, include:

- Framework version
- PHP version
- SQL Server version
- ODBC Driver version
- Steps to reproduce
- Expected behavior
- Actual behavior
- Error messages or logs

---

# Pull Requests

Before submitting a pull request:

- Ensure the project builds successfully.
- Verify that existing functionality continues to work.
- Update documentation if necessary.
- Keep commits focused on a single change.

---

# Code Style

Please follow the project's coding conventions:

- Meaningful variable names
- Consistent indentation
- Proper comments where necessary
- Modular design
- Avoid duplicated code

---

# Feature Requests

Feature requests are welcome.

Please describe:

- The problem
- Proposed solution
- Expected behavior
- Possible implementation approach

---

# Questions

If you have questions about the framework, open a GitHub Discussion or create an Issue.
